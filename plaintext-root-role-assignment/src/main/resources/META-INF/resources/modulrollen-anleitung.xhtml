Modul-Rollen – Anleitung (admin)

Diese Anleitung ist für admin. Sie erklärt, wie du steuerst, wer welches Modul benutzen darf – und woran du erkennst, dass ein Problem nicht bei dir liegt.

1. Deine Zuständigkeit

Zwei Fragen, zwei Zuständige – und sie werden oft verwechselt:

FrageWerWo
Wer darf ein Modul benutzen? admin – du Admin → Rollenzuteilung, bzw. Benutzerverwaltung
Welche Module gehören überhaupt zu diesem Mandanten? root Root → Menüsteuerung

Du vergibst Rollen. Ob ein Modul für den Mandanten überhaupt freigeschaltet ist, entscheidet root – und keine Rolle hebt das auf. Das ist der wichtigste Satz dieser Seite; Abschnitt 5 erklärt, was das praktisch heisst.

2. Was eine Modul-Rolle bewirkt

Eine Modul-Rolle ist eine Rolle, die eine Anwendung einem ganzen Modul zugeordnet hat (in der Konfiguration, z.B. wiki → ROLE_WIKI). Wer sie nicht hat, für den ist das Modul nicht vorhanden:

  • der Menüpunkt und alle Untermenüs sind unsichtbar,
  • die Dashboard-Kachel ist unsichtbar,
  • der Direktaufruf per URL wird abgewiesen.
admin und root umgehen diese Prüfung immer. Du siehst also auch Module, für die du die Rolle gar nicht hast – ein Grund mehr, Sichtbarkeitsfragen nicht an deiner eigenen Ansicht zu prüfen, sondern beim betroffenen Benutzer (Impersonate).

Modul-Rollen sind reine Zugangsrollen zu einem Fachmodul. Sie verleihen keine Verwaltungsrechte – deshalb darfst du sie vergeben.

3. Rolle an einen Benutzer vergeben

Es gibt zwei Wege; beide führen zum selben Ergebnis:

Admin → Rollenzuteilung (empfohlen)

  1. Neu anklicken.
  2. Benutzername eintragen (die Login-/E-Mail-Adresse).
  3. Rolle aus der Liste wählen – sie enthält alle von den Modulen deklarierten Rollen plus die bereits vergebenen.
  4. Aktiv anhaken und speichern.

Zur Rollenzuteilung

Benutzerverwaltung

Unter Admin → Benutzer kannst du die Rollen direkt am Benutzer pflegen. Das ist praktisch, wenn du ohnehin gerade andere Angaben änderst.

Eine neu konfigurierte Modul-Rolle hat zunächst niemand. Direkt nach dem Einrichten sehen nur admin und root das Modul – alle anderen erst, wenn du ihnen die Rolle gegeben hast. Wirksam wird sie beim nächsten Anmelden des Benutzers.

4. Welche Rollen es gibt

Die Auswahlliste zeigt die Rollen, die die Module deklariert haben – mit Beschreibung, damit du nicht raten musst. Dazu kommen die Rollen, die im Bestand schon vergeben sind. Rollen, die eine Anwendung einem Modul zugeordnet hat, erscheinen automatisch mit einer Beschreibung wie „Zugriff auf das Modul wiki".

Teilen sich mehrere Module eine Rolle (etwa finanzen für Rechnungen, Buchhaltung und Postkonto), öffnet eine Vergabe alle davon – das steht dann auch so in der Beschreibung.

5. Zusammenspiel mit den Mandanten-Listen

Ein Menüpunkt erscheint nur, wenn alle vier Filter Ja sagen:

  1. Rolle am Menüpunkt – dein Bereich.
  2. Modul-Rolle – dein Bereich.
  3. Modul aktiv (Root → Module) – root.
  4. Mandanten-Liste (Root → Menüsteuerung) – root.
Die Rolle hilft nicht gegen den Mandantenfilter. Wenn ein Modul für den Mandanten nicht freigeschaltet ist, ändert auch die grosszügigste Rollenvergabe nichts. Symptom: du hast die Rolle vergeben, der Benutzer sieht trotzdem nichts – und es betrifft alle Benutzer dieses Mandanten gleichermassen.

Die Faustregel zur Abgrenzung: Betrifft es einen Benutzer, während Kollegen im selben Mandanten das Modul sehen, ist es eine Rolle – dein Fall. Betrifft es alle Benutzer eines Mandanten, ist es die Mandanten-Liste – ein Fall für root.

6. Wann du root brauchst

SituationWarum nicht du
Ein Modul soll für einen ganzen Mandanten sichtbar/unsichtbar werden. Das ist die Mandanten-Liste (Root → Menüsteuerung).
Ein Modul ist global abgeschaltet. Root → Module.
Jemand soll die Rolle admin oder root bekommen. Verwaltungsrechte vergibt nur root – sonst könnte admin seine eigene Beschränkung aufheben.
Jemand soll zwischen Mandanten wechseln (PROPERTY_*). Wirkt über den eigenen Mandanten hinaus – nur root.

Versuchst du eine dieser Rollen zu vergeben, lehnt das System es mit einer klaren Meldung ab. Bestehende Zuweisungen bleiben davon unberührt und weiter editierbar – es geht nur um das Neu-Vergeben.

7. Kurzrezepte

„Neuer Mitarbeiter soll die Rechnungen sehen."
Admin → Rollenzuteilung → Neu → Benutzername + die Rolle des Rechnungs-Moduls → Aktiv → Speichern. Der Benutzer muss sich neu anmelden.
„Rolle vergeben, er sieht es trotzdem nicht."
Hat er sich neu angemeldet? Wenn ja und es betrifft alle im Mandanten: root bitten, in der Menüsteuerung nachzusehen (Abschnitt 5).
„Jemand soll ein Modul nicht mehr sehen."
Zuteilung auf inaktiv setzen oder löschen. Gilt ab der nächsten Anmeldung.
„Ich weiss nicht, welche Rolle das Modul braucht."
Die Beschreibungen in der Rollen-Auswahl nennen das Modul. Hilft das nicht weiter, kann root es in der Menü-Diagnose direkt ablesen – dort steht bei jedem Menüpunkt, welche Rolle fehlt.
